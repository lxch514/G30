# 2026-10-27 六路重连与 camera2 无画面复查

当前运行目录 `/root/G30`，六路1920×1080、30fps、H.264每路2Mbps、单连接TCP。仅调整运行配置，未改采集/编码/传输源码、APK、辅助线设置、网卡或光纤配置；未启动或修改G30_mix、snappy-real。

## 原因

1. 六台相机和两个Hub均已枚举。camera2在5秒内收到150帧，但完整JPEG为0、残缺帧150；因此没有可供编码的画面。
2. 旧配置给camera0分配3072，给camera2分配1024。把较大额度转给camera2曾恢复六路，并通过第一轮两分钟验证；但继续观察后发现其他通道又出现残缺。最终重新平衡为1536/1536/2048/1536/1536/1536。额度是USB采集每微帧的字节额度，不是H.264的2Mbps网络码率。
3. `capture_supervisor.py` 在启动8秒后检查各路最新帧。只要一路缺失或超过5秒不更新，就重启整组六路，随后等待3秒重试。因此camera2故障会使正常通道也周期性重连。
4. 内核在16:07:44、16:07:49记录到camera5（USB路径7-1.2）断开并重新枚举，用户确认期间没有插拔或移动连接线；还出现xHCI无法及时访问内存的告警。该问题与残缺帧分开记录，尚不能确定具体是线缆、Hub供电、相机还是控制器/驱动因素。

无法仅凭这次记录确认是调换了哪一台相机或哪个插口。已通过调整额度的对照验证确认当前分配不匹配。

`/root/G30/config/g30.json` 中，按camera0～5顺序：

## 后续使用

保留当前两个Hub和各摄像头的插口位置。编号按USB Bus升序、Hub物理端口降序分配；相机序列号不能可靠区分六台身份，固定额度不会自动跟随被移动的相机。更换插口、相机、模式或观察场景后，应检查 `incomplete_frames` 是否增长并重新验证。

本次未增加自动额度选择或单路独立恢复；监督程序的整组恢复策略仍在。因此若另一路以后持续异常或再次发生USB自行断开，仍可能触发整组重启。当前画面已恢复，但自行掉线的具体原因尚未根治；后续应优先检查camera5对应线缆、Hub供电和端口，再结合新内核日志判断控制器因素。这次验证不能替代长时间工况验收。
