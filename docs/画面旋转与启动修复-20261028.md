# G30 v1.4.0：六路180°转正与启动错误修复

2026-10-28，板端 `/root/G30` 与遥控器APK已同步更新，当前六路1920×1080、30fps、每路H.264 2Mbps、TCP。

## 修改画面方向

编辑开发板 `/root/G30/config/g30.json`：

```json
"display_rotation_degrees": [180, 180, 180, 180, 180, 180]
```

六个值依次对应camera0～5。`180`表示遥控端把画面旋转180°，`0`表示保持原始方向；目前只接受这两个值。只需某一路转正时修改对应位置，例如 `[0,0,180,0,0,0]`。

保存配置后按原方式重新启动本项目：

```bash
bash /root/G30/scripts/start.sh
```

参数保存在板子的文件系统中，正常断电重启后仍会读取。APP v1.4.0从状态接口取得设置，由 `CameraTile.rotation()` 对视频TextureView调用 `setRotation()`；摄像头编号、统计文字及camera0/camera1辅助线保持正向。六宫格和点击全屏共用相同视频视图。此配置不会修改原始JPEG或H.264像素方向；独立G30_mix或其他接收程序需要自行处理方向。

## 启动错误

板端 `board/g30_service.py` 配置校验字段被误写成 `lease_seco nds`，导致启动报 `Invalid configuration: lease_seco nds`。已修复为正确的 `lease_seconds`，并增加配置回归检查。配置文件的正确键名保持不变。

## 实现与安装

- `board/g30_service.py`：校验六路显示角度，将 `display_rotation_degrees` 提供给APP。
- `remote/android/.../MainActivity.java`：状态轮询取得角度，更新各画面。
- `remote/android/.../CameraTile.java`：GPU只旋转视频层，保留文字和辅助线方向。
- `board/h264_encoder.py`：最终保持原编码流程。板端硬件旋转试验曾出现停滞和缓冲区警告，已撤回该试验，未更换系统库。
- APK v1.4.0已安装。因旧APK签名与电脑当前调试签名不同，升级前保存了旧APK及唯一的配置XML，再重装并恢复配置；恢复文件逐字校验一致，已有连接和辅助线参数保留。临时旧版本备份按用户要求在验证完成后清理。

之后在本电脑使用相同调试签名编译，可正常覆盖安装。已构建APK位于 `dist/g30-sixcamera-debug.apk`；源码包位于 `dist/G30-project.zip`。
