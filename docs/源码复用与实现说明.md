# 源码复用与实现说明

## 参考来源

1. 用户原六路 H.264 目录：`uvc_cap_test.c`、`h264_encoder.py`、三个 ARM64 构建依赖 deb。H.265 存档中的同名 H.264 文件与它们一致。
2. 板端 `/root/snappy-real/rk3588/gateway/src/g20/g20_video.cpp`：MJPEG → MPP → H.264 → RTP 的既有通信格式；PT 96、MTU 1200。
3. 板端 Android `VideoPanel.kt` 和 `RtpH264AccessUnitDepacketizer.kt`：UDP 接收、NAL/FU-A/STAP-A 重组、MediaCodec 低延迟输出的既有逻辑。
4. G30/G20 用户说明书：Android 应用安装、屏幕、RJ45 与第三方图传的产品背景。说明书中的航电/串口接线步骤没有作为本视频项目的操作指令执行。

## 复用与改造

- `board/uvc_cap_test.c` 从原六路源码适配，保留 0bda:2292 筛选、Bus/物理端口排序和最新 JPEG/状态发布。1080p 修复增加逐路 payload 配置、JPEG 完整性检查和残缺帧统计；有效帧才计入采集帧率并发布。`capture_supervisor.py` 将配置的六路额度传入采集程序，当前依次为 3072/1024/1024/1536/1536/1536。用户随后要求删除板端历史备份，目前板端仅保留现用程序。
- `board/h264_encoder.py` 从原编码模块适配：保留 MPP 管线和有界订阅队列；加入 GI 枚举在主线程预热、串行构造初始管线、采集离线处理、无输出重建和 FLUSHING 时间戳清理。JPEG 解码使用 BSP 默认且与旧 G20 一致的 `ignore-error=true`，避免单个输入错误立即使整条实时管线退出；仍保留无输出超时重建，不能据此声称 USB 输入没有任何损坏。
- G30 是原生 APP，复用 G20 的 MediaCodec 低延迟解码逻辑；按用户要求，APP 的状态和视频通信全部使用 TCP。Java RTP 重组器从旧 Kotlin 逻辑改造后保留为协议对照代码，APP 不启用 UDP 接收。
- 六个 TextureView/解码器分别对应六路；全屏仅改变同一组 View 的布局，选中单元盖住其他单元，背景表面保持可绘制以排空帧队列。
- 不采用旧工程的“切换 camera1/camera2”命令；新服务同时维护六路编码，APP 同时接收和解码六路。
- 默认 TCP 直接复用原网页 H.264 的 16 字节包头多路复用协议，`FramedFeed` 在原生 APP 中拆包后送入六个 MediaCodec，只需 8096 一个端口，适配 GR03/G30 百兆光纤和可能的路由转发。
- 服务保留 RTP 对照测试接口，但只有显式注册时才发送，APP 不注册此接口。APP 只用 TCP 8096，与旧清洗工程分开。
- RTP 使用每路编码帧序列对应的 90kHz 表示时钟，避免文件修改时间抖动进入 RTP 播放时间轴；没有把这个时钟作为光学延迟测量依据。

## 资料与标准

TCP 视频采用 HTTP `GET /api/feed`，返回持续的二进制数据。每个访问单元先发 16 字节大端包头，再发指定长度的 Annex-B H.264 数据：

| 字段 | 字节数 | 含义 |
|---|---:|---|
| camera | 1 | 通道 0～5 |
| key | 1 | 是否关键帧 |
| reserved | 2 | 保留 |
| capture_us | 8 | 板端采集时间戳，微秒 |
| length | 4 | 后续 H.264 访问单元的字节数 |

TCP 可以拆分或合并网络数据，APP 使用 readFully 按长度读取，不假设一次 read 就是一帧。每路新订阅从自己的关键帧开始，SPS/PPS 随 IDR 发送。板端每个订阅有界缓存，TCP 积压时清空过期队列，分别等待六路各自的新 IDR，不重建 TCP；从而保留拥塞控制状态，并避免只丢 P 帧后继续使用断裂的参考链。旧 RTP 对照接口保留超限断开策略。APP 解码队列也是有界的，过旧数据丢弃后等下一关键帧，以限制延迟累积。此 HTTP 服务提供本 APP 的码流，不是 RTSP 服务。

- G30 PDF 参数页标明 Android 14、1920×1200、8GB RAM 和 RJ45。无线空口参数并不代表当前光纤路径带宽，本项目没有据此对光纤速度作推断。
- [RFC 6184：H.264 RTP 负载格式](https://www.rfc-editor.org/rfc/rfc6184.html)
- [Android MediaCodec](https://developer.android.com/reference/android/media/MediaCodec)
- [Android getMaxSupportedInstances](https://developer.android.com/reference/android/media/MediaCodecInfo.CodecCapabilities#getMaxSupportedInstances())：只是并发数量上限的提示，实际资源可能让可用数量更少。
- [Linux DWC3 debugfs 源码](https://github.com/torvalds/linux/blob/v6.1/drivers/usb/dwc3/debugfs.c)：`mode` 接口支持运行时选择 Host；本板重启后角色为 Device，现场切到 Host 后恢复六台枚举。初始化已加入本项目启动脚本。
