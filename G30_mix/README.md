2026-10-28 更新。独立运行于 `/root/G30_mix`，读取 `/root/G30/run/frames/cam0.jpg`～`cam5.jpg` 的最新画面。支持 camera0～5 任选1～6路：单路直接预览，多路对有重叠的画面做对齐、投影和接缝融合。六路默认均先旋转180°，缩略图、固定选点图和最终融合图方向一致。

## 选择、对齐和调整位置

1. 在“选择画面与180°转正”勾选需要的camera，选一台作为基准，点击“保存选择”。默认六路都是180°，也可单独切回0°。**改变所选组合或所选相机的转正角度，会清除该组的对应关系和位置微调，需要重新对齐。**
2. 点击“自动对齐所选画面并保存”。可选择整幅、上部65%或上部45%用于找对应点。选墙面等同一平面上的清晰纹理，避开近处机器人和线缆。自动匹配只在点击时进行，实时阶段复用已经保存的变换。
3. 自动失败时，展开“逐对手动选点”，点击“拍摄固定标定图”，选择左、右两台camera，依次点击相同位置的对应点，至少4对，建议6～10对，分散且不共线。点击“保存本对对应关系”。可换另一对继续建立连接，直到全部选中相机连到基准。
4. 在“上下左右位置与融合”选择要微调的camera，用箭头、X/Y输入或拖动彩色布局示意图调整。X向右为正，Y向下为正，单位是**基准画面原图坐标的像素**。箭头默认每次20像素，可改步长。拖动的是下方布局示意图，顶端是真实融合结果。
5. 应用成功的位置修改会立即保存；“恢复全部位置微调为0”清除偏移，保留对应关系。双路可调接缝位置；三路以上按有效覆盖区自动划分接缝，并做窄带融合。改变融合宽度后点击保存。
6. “整体拉正与裁黑边”可微调水平角度，或按基准画面的竖线估计角度。裁黑边会减少边缘视野，可能无法容纳所有源画面中心而被拒绝；关闭裁黑边可保留完整联合视野。

**上下左右是已对齐图像的位置微调。** 真实融合中画面的相对位置主要取决于共同内容；把相机随意移到没有重叠的位置，不能继续形成可信接缝。明显超出有效重叠或几何异常的修改会被拒绝，并保留上一次已保存的参数。

所选相机可以通过另一台间接连接，例如0与2有重叠、2与4有重叠，即使0与4不直接重叠也可以组成一幅图。完全不重叠、无法建立连通关系的组合，会指出哪些camera缺少连接；手动点也必须是真实对应点。

## 设置保存和启动

**当前唯一主配置：`/root/G30_mix/config/project.json`。** 保存摄像头选择、基准、六路转正角度、各路位移、对应关系、接缝、整体拉正和裁剪。程序校验并试渲染成功后，通过临时文件、fsync和原子替换保存；重新启动服务自动加载。摄像头安装位置、观察平面距离、焦距或分辨率改变后，应重新检查并标定。

旧版 `config/calibration.json`、`config/view.json` 仅在首次没有project.json时用于迁移；已迁移后请通过网页修改project.json中的设置。不要把删掉project.json当作常规复位操作。

板子重新上电后，如果原采集尚未启动，先按原项目方式启动，再启动融合：

```bash
bash /root/G30/scripts/start.sh
bash /root/G30_mix/scripts/start.sh
```

只重启融合服务：

```bash
bash /root/G30_mix/scripts/stop.sh
bash /root/G30_mix/scripts/start.sh
```

本次未改系统开机自启、网卡或网关配置。配置文件保存在板端，正常重启/断电后重新启动程序会读取保存值；已验证测试实例重启恢复，未进行整块板子实际断电试验。原APP的辅助线参数仍保存在遥控器，与本项目独立。

## 代码和实现

```text
原六路采集发布JPEG文件（只读）
    → 所选camera解码 → 各路180°转正
    → 已保存的平面变换＋各路X/Y＋整体角度
    → 有效覆盖区选缝、曝光增益补偿、窄带融合
    → JPEG最新帧缓存 → HTTP/TCP 8097 → 网页
```

- `server.py`：主入口，HTTP接口、MJPEG预览、请求和连接数限制。最多4个预览连接，慢客户端取最新帧。
- `project_app.py`：画面读取、项目保存、自动/手动校准任务、实时处理线程及状态接口。失败保留上一次已接受的设置。
- `mosaic.py`：多路连接图、单应矩阵组合、180°旧参数迁移、位置偏移、画布与覆盖校验、多路接缝融合。自动建立可靠关系后，以连通树将每路变换到基准坐标。
- `core.py`：复用原SIFT特征、BF描述子匹配、RANSAC单应变换、手动对应点校验、竖线角度估计和有效区域裁剪等OpenCV逻辑。
- `web/index.html`：网页全部界面与交互，包括相机勾选、自动对齐、手动点、布局拖动、箭头微调及拉正。
- `config/mix.json`：服务/编码参数；`config/project.json`：当前组合及几何参数。
- `scripts/start.sh`、`stop.sh`：只管理本目录的服务。
- `run/`：运行PID和启动锁；`logs/`：服务日志；`samples/`：有限的标定图和验证快照，不持续录像。
- `tests/`：26项几何、异常输入、连通关系、旋转、保存失败保护、持久化和方向一致性测试。
- `tools/validate_multicam.py`：只读实机验证，解码20帧TCP预览并观察原六路状态。旧验证入口也转到这个工具。

## 参数和速度

当前 `config/mix.json`：输出上限1600×1000、目标8帧/秒、JPEG质量82、OpenCV线程2、文件到达差上限80ms、源文件最大年龄1秒。输出实际宽高由所选画面、变换与裁剪决定。修改mix.json后只重启本项目。

网页融合是 **MJPEG / HTTP / TCP**，没有固定“每路2M”的码率；流量随合成JPEG大小、实际帧率和观看连接数变化。原H.264六路的2Mbps、1080p、30fps及USB配额均由原G30项目管理，本次没有修改。

多路处理会增加CPU开销，目标8fps不代表任何组合都能达到8fps。本次camera3＋camera4约8fps；同时保留两路预览的测试条件下，六路真实融合约3fps，具体中位值见验证报告。全部六路更适合先验证安装与重叠，实际使用可按需要选两三路。输入文件到达差是采集程序发布文件的时间差，不能当作摄像头曝光同步或整条链路延迟。

## 验证和边界

本次验证包括26项测试、JavaScript语法、真实网页按钮/拖动/缩略图/选路/固定选点图、实机六路自动融合、TCP预览解码、参数保存恢复及原六路并行观察。详细记录见 `docs/multicam-*.json` 和 `docs/多路融合验证.json`；旧“画面拉正”“初始拼接”报告是早期版本记录。

复测：

```bash
cd /root/G30_mix
python3 -m unittest discover -s tests -v
python3 tools/validate_multicam.py --seconds 15
```

这是单平面近似拼接，尚未做真实镜头内参/畸变标定。不同深度的物体不能同时保证对齐，当前室内近处桌面、线缆仍有错位、重影，动态物体也会影响接缝。自动匹配误差是参与标定点的误差，不能代表所有物体都达到同样精度。相机固定、同一平面、充分重叠时更适合此方法。

不提供真实三维距离、自动避障或机器人控制。原始六路画面仍可用于核对靠近机器人及接缝处物体。网页在电脑的隔离Edge实例完成交互验证，尚未在G30浏览器逐项操作或进行长时间可靠性验收。

源码包里的project.json是打包时快照。之后在网页保存会更新板端配置，以板端最新保存值为准。
