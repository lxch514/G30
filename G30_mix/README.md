## 启动、停止

输入依赖原项目的采集程序已经在运行。若板子重启、原采集未启动，先按原方式启动：

```bash
bash /root/G30/scripts/start.sh
```

然后启动这个试验：

```bash
bash /root/G30_mix/scripts/start.sh
```

已有标定会自动加载，不需要每次重新对齐。没有输入时网页显示等待，不会自动抢占 USB 或启动原 G30。停止这个拼接服务：

```bash
bash /root/G30_mix/scripts/stop.sh
```

只重启拼接服务：

```bash
bash /root/G30_mix/scripts/stop.sh
bash /root/G30_mix/scripts/start.sh
```

上述停止脚本仅处理本目录的 server.py 进程；不停止原六路采集和编码。未配置系统开机自启，未修改网卡、网关或光纤配置。

## 如何调整拼接

页面展开“调整拼接与接缝”：

1. 固定两台相机，确保两路看到同一部分墙面。点击“自动对齐并保存”，默认优先匹配图像上部65%，可切换整幅画面或上部区域。
2. 自动结果不好时，点击“拍摄标定图 / 手动选点”，两侧图像会固定。按相同顺序选择同一面墙上的对应点，至少4对，建议6～10对，覆盖较大区域并避免集中或共线。不要混用不同距离的墙、椅子和桌沿作为同一个平面。
3. 点击“应用手动选点并保存”。失败会说明原因，保留之前已接受的标定。
4. 可移动“接缝在重叠区的位置”，点击“应用接缝并保存”。尝试让接缝经过平坦背景，避开机器人、线缆、工具或近处障碍物。

参数保存在 `/root/G30_mix/config/calibration.json`，采用临时文件写入、fsync 和替换；通过几何与试渲染检查后才保存。重启拼接服务可以恢复标定和接缝位置。板子重新上电后，仍需先启动采集和拼接程序；本次未进行实际断电重启试验。摄像头位置、焦距、输入尺寸或与观察平面的关系改变后，应重新检查并标定。编号继承原项目，重新插接时保持 Hub 和相机端口位置。

这里的参数保存在开发板，与原 APK 中 camera0/camera1 辅助线保存在遥控器的设置互不影响。

## 实现过程

```text
原六路 USB 采集 → /root/G30/run/frames/cam3.jpg、cam4.jpg
                       ↓ 只读最新完整帧
              JPEG解码 → 固定几何变换 → 接缝融合
                       ↓
               JPEG预览 → HTTP/TCP 8097 → 浏览器
```

原六路 MJPEG→硬件H.264→TCP→G30 APP 的流程继续运行。

- `core.py`：读取完整发布文件，检查文件新鲜度和两路发布时差；SIFT 匹配、RANSAC 平面单应变换；检查可靠点数量、空间分布、重投影误差和有效重叠，拒绝退化或异常画布。手动点也经过检查。
- 可使用camera3或camera4作为基准视角；原始居中视角使用矩阵平方根把透视校正分配到两幅图。视角、共同旋转和裁剪合并进固定映射，实时帧不重复匹配。
- 对曝光差做有界的全局通道增益补偿；初次选择重叠区差异较小的接缝，并使用较窄融合带，减少大范围叠加产生的近景重影。接缝可手动改变。
- `server.py`：固定帧率处理、最新帧缓存、标定保存、网页控制和 HTTP/TCP 预览；慢客户端只取最新完整 JPEG，不积压无界队列，最多4个预览连接。
- `web/index.html`：拼接结果、状态、画面拉正、自动校准、手动选点和接缝调节。
- `scripts/start.sh`、`stop.sh`：只管理本项目的进程。
- `tests/test_core.py`、`tests/test_view.py`：几何、异常输入、内容保留、拉正与覆盖区裁剪、保存/恢复测试，共18项。
- `tools/validate_live.py`：初始拼接验证；`tools/validate_view.py`：20帧拉正预览解码及约15秒与原六路并行观察。后者不拍摄选点参考图。
- `samples/`：有限的标定原图、对应点、标定结果及验证快照，不持续录像。
- `run/`：本项目 PID 和启动锁；`logs/server.log`：本项目日志。

两路输入时间采用已打开文件的修改时间，属于**采集程序发布文件的时间**，不是摄像头曝光同步时间。默认允许最多80ms的发布时差，超过阈值不继续输出新的拼接帧；不把共用TCP连接视为硬件同步。

## 参数修改

编辑 `config/mix.json` 后，只重启 G30_mix：

- `fps`：预览目标帧率，当前8；提高前需复测板端负载。
- `max_width/max_height`：输出画布上限，当前1600×1000；实际尺寸取决于变换与画布范围，当前拉正并裁黑边后为1583×537，原始居中视角为1600×737。
- `jpeg_quality`：当前82，影响预览清晰度、CPU与流量。
- `blend_width_pixels`：当前12，窄接缝附近的融合宽度。
- `source_dir`：只读帧来源，当前 `/root/G30/run/frames`。
- `port`：预览TCP端口，当前8097；原六路服务端口仍为8096。

本试验预览是 MJPEG/HTTP/TCP，**不是新增一路固定2M的H.264**；流量随JPEG大小、帧率及观看端数量变化。若以后接入原 APK，可另行增加 H.264 输出和通道适配。本次未进行该改造。

## 适用边界

当前是**单平面近似的双路拼接试验**，尚未做镜头内参/畸变标定，不是三维重建或汽车360鸟瞰。当前门、墙等背景可以接到一起；近处桌沿仍有明显的视差接缝，移动物体或观察距离变化也可能出现缺口、重影、重复或局部遮挡。不能通过平面变换同时保证所有深度的物体连续。

对于高空清洁机器人，应以原始相机画面核对靠近机器人或接缝的物体。此版本不输出真实距离、不识别障碍，也不发出机器人控制指令。

后续运行日志另出现过输入JPEG解码告警（例如图像数据段提前结束）。本版尚未自动剔除所有可恢复的损坏JPEG，可能出现局部图像异常；该输入质量问题未在本次修改原采集程序处理。30秒观察中残缺帧计数不增加，不等于所有JPEG内容始终无损。当前仍属于拼接试验版本。

源码包中的标定、视角设置与样例是打包时的快照。网页修改接缝、重新标定或保存拉正后，板端配置会更新，不能要求其哈希永远与源码包中的快照一致；部署文档和程序文件仍单独校验。
